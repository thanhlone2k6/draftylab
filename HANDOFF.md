## Gotchas
- **Waitlist (2026-11-07):** the public counter is `48 + active rows`, capped at 100 (`src/lib/waitlist.ts`); `GET /api/waitlist` never returns the email list. `POST` uses its own `waitlist_rate` table and rejects after 5 tries / 10 min / IP (the Quick Call quota is separate). The owner gets one Resend/Telegram email per **new** signup with `reply_to` = the registrant, so the welcome mail is manual. Migration `0008` stores `consent_at/version/text` even though the UI uses a notice line (no checkbox). Keep `functions/api/waitlist.ts` path exact: the client always fetches `/api/waitlist`.
- **Waitlist Turnstile (2026-11-07):** production has `TURNSTILE_SECRET`, so `/api/waitlist` requires a valid token. The client renders the widget only when `PUBLIC_TURNSTILE_SITEKEY` is set and reads the hidden `cf-turnstile-response` field as a fallback because `appearance="interaction-only"` can hide the callback. If the widget is blocked, signups return 403 captcha. The console shows Cloudflare's own `data:,` CSP warnings inside the Turnstile iframe plus the known blocked Web Analytics beacon; they do not block signups.
- **PostHog (2026-11-06):** the inline loader lives in `src/components/analytics/PostHog.astro` and the public key is in `package.json` (`build:cf` / `build:preview`). Keep `https://us-assets.i.posthog.com` in `script-src` and `https://us.i.posthog.com` in `connect-src` or tracking silently dies. No consent banner (owner chose C); the privacy policy discloses PostHog. Do not add `session_recording`/autocapture without revisiting the policy.
- **Lead migrations (2026-11-06):** the insert now writes `consent_at`, `consent_version`, `consent_text` and `source`. Apply `migrations/0006_lead_consent.sql` + `migrations/0007_lead_source.sql` to production **before** the deploy that contains this code, or every lead submit will fail with a 500.
- **Privacy page stays out of the client bundle:** `src/data/privacy.ts` is imported only by `BaseLayout`, `Footer` and `PrivacyPage` (all server-rendered). Do not import `PRIVACY` into `src/i18n/index.ts` — that would ship all five policies to every client island.
- **Cloudflare Web Analytics is deliberately blocked by the CSP** (`scripts/prepare-dist.mjs` no longer allows `static.cloudflareinsights.com` / `cloudflareinsights.com`). Turn it off in the Cloudflare dashboard; otherwise the browser logs a blocked-script error on every page.
- **Do not remove `build.cssMinify` or `build.target`/`cssTarget` from `astro.config.mjs`**: Vite 8's defaults strip `backdrop-filter` (frosted glass gone in Chrome) and break older iPhones. Build and tests stay green either way, so only a browser comparison shows it.
- **CSP is enforced**: a new outside service (script, iframe, image, API) is blocked until its domain is added in `scripts/prepare-dist.mjs`. Inline scripts are hashed automatically at build. Cloudflare injects scripts at deploy time that a local build never shows, so check the real preview URL too.
- **`ADMIN_ENABLED` must stay "false" on preview** (`wrangler.toml`): preview shares the real D1/R2, so an admin there would edit live posts. On localhost with no `RESEND_API_KEY`, the login code prints to the wrangler log instead of being emailed.
- **Community labels live in `src/i18n/overrides.ts`** (they have no row in the review file). Post content is never translated.
- **Community order is `COALESCE(sort_order, created_at) DESC`**: dragging in /admin writes `sort_order`; posts never dragged keep newest-first, and a new post (NULL) still lands on top. Editing the date only changes the label — it does not move the card once the list has been reordered.
- **Skills use the same order rule** (`community_skills`, seeded 3000/2000/1000). Skill covers live in the same R2 `community/` folder and are served by `/api/community/image/:key`; `image_key = ''` means "no cover" and the shelf shows the code icon.
- **`CoverField` is shared by the post form and the skill form**, and both are mounted at once in /admin — its paste listener is scoped to `closest('form')` on purpose. Reverting it to `document` makes one ⌘V open two croppers. The AnimatedList is vendored (`@ts-nocheck`); feed it through `SkillList.tsx` instead of editing its internals.
- **Skill shelf must not trap the page wheel (2026-11-07):** `SkillList` passes `maxHeight="none"` and `AnimatedList.css` uses `overscroll-behavior: auto` (was a capped height + `contain`). Restoring either makes the mouse wheel scroll the shelf instead of the page when the pointer is over it — the owner reported this.
- **Community hover styles must stay inside `@media (hover: hover) and (pointer: fine)`**: an unguarded `:hover` on the card makes a phone's first tap show the hover state instead of following the link (owner, 2026-11-05).
- **/admin uploads are cropped square in the browser** (`ImageCropper.tsx`, output ≤1400²). Images published before round 3 are still their original ratio and the card crops them; use **Chỉnh lại / cắt ảnh** to make them square. CSS shows exactly one per width and the teaser is `aria-hidden` + `inert`, so don't "de-duplicate" it. The teaser row only exists when there are more posts than the 3 shown.

- **Dev-only Vite trap**: a lazily-imported island (`client:visible`) can 504 on its first request when its deps were not pre-bundled — that is what made the case-study counters sit at `0.0K` on every page ("sang các ngôn ngữ khác thì không chạy"). `optimizeDeps.include` in `astro.config.mjs` prevents it; if a dev page looks dead, look for `504 Outdated Optimize Dep` in the console before blaming the code.

Re-pinning it to `width - header` puts the menu back in the corner. The nav only folds below ~559px, so that is the range to test in.
